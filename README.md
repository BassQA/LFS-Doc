# LFS Restoration Guide

### 1. Create and Format Partitions (Partitioning)
Using a tool like `cfdisk`, she will create the partition scheme. To match your project, she would need four partitions:
- One for Root (`/`)
- One for `/boot/efi` (Size: ~200MB, Type: EFI System)
- One for `/boot` (Size: ~200MB, Type: Linux)
- One for Swap (Size: ~2G, Type: Linux swap)

Next, she formats each one (e.g., `mkfs.ext4` for the Linux partitions, `mkfs.vfat` for the EFI partition, and `mkswap` for the Swap).

### 2. Mount the structure in the correct order (Mounting)
She needs to mount the partitions so the filesystem structure matches yours:

```bash
mount /dev/sdX_RAIZ /mnt/lfs
mkdir -p /mnt/lfs/boot
mount /dev/sdX_BOOT /mnt/lfs/boot
mkdir -p /mnt/lfs/boot/efi
mount /dev/sdX_EFI /mnt/lfs/boot/efi
```

### 3. Download and Extract the Backup (Unpacking)
She downloads your `.tar.gz` file and extracts everything directly into the root of the new disk:

```bash
tar -xpf lfs-backup.tar.gz -C /mnt/lfs --numeric-owner
```

### 4. Update fstab with the new UUIDs (fstab Adjustment)
This is where your point comes in. Since her partitions were just created, the physical identifiers (UUIDs) are completely different from yours.

run the `blkid` command to find out the new numbers and edit the `/mnt/lfs/etc/fstab` file generated by the backup, replacing the old UUIDs with hers. This ensures the system knows where to mount `/`, `/boot`, `/boot/efi`, and the swap during boot.

### 5. Enter chroot and install GRUB (The Missing Step)
Just changing `fstab` organizes the system on the inside, but the motherboard still doesn't know there is an operating system there.

mount the virtual directories (`/dev`, `/proc`, `/sys`, `/run`), enter the isolated environment using the `chroot` command, and write the bootloader to her motherboard's NVRAM:
 
```bash
mount -vt devpts devpts -o gid=5,mode=0620 $LFS/dev/pts
mount -vt proc proc mnt/lfs/proc
mount -vt sysfs sysfs mnt/lfs/sys
mount -vt tmpfs tmpfs mnt/lfs/run
```

```bash
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=LFS --recheck
grub-mkconfig -o /boot/grub/grub.cfg
```
 Now that all the packages which are required to build the rest of the needed tools are on the system, it is time to enter the chroot environment and finish installing the temporary tools. This environment will also be used to install the final system. As user root, run the following command to enter the environment that is, at the moment, populated with nothing but temporary tools: 

```bash
chroot "$LFS" /usr/bin/env -i   \
    HOME=/root                  \
    TERM="$TERM"                \
    PS1='(lfs chroot) \u:\w\$ ' \
    PATH=/usr/bin:/usr/sbin     \
    MAKEFLAGS="-j$(nproc)"      \
    TESTSUITEFLAGS="-j$(nproc)" \
    /bin/bash --login
```

# LFS Security Hardening & Permissions

## 1. What We Configured

* **File Ownership:** All main folders (`/bin`, `/etc`, `/usr`, `/lib`, etc.) belong to `root:root` to remove any leftover files from the `lfs` build user.
* **Password Protection:** Set `/etc/shadow` to `600` so only `root` can read password hashes.
* **SUID Limits:** Only `passwd` and `su` have the SUID bit (`4755`) so normal users can change passwords and switch users. Tools like `mount` and `umount` stay at `755` for safety.
* **Wheel Group:** Added `SU_WHEEL_ONLY yes` in `/etc/login.defs`. Only members of the `wheel` group can run `su -`.

# Configuration Tracking with Git in /etc

## 1. Why Git in /etc?

* **Audit & History:** Tracks every change made to system configurations, recording who changed what and when.
* **Instant Recovery:** Lets you roll back broken or accidentally edited files in seconds without needing system reinstalls.
* **Integrity Baseline:** Provides a clean "checkpoint" of the system at delivery time.
* **Security:** The `/etc/.git` folder is locked to `root:root` (`chmod 700`) to prevent unprivileged users from reading historical changes or secrets.
